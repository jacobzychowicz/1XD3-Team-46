Section 2 - Purpose

The app is a blog that shows scientific articles to high schoolers. It allows users to log in and comment on the posts and reply to comments, while it allows the writer to post articles and perform the same functions as the users.

The client wanted a way to share his research with his peers or other people, so we decided on making a blog-type web app, with features he has requested.

Section 3 - Data Descriptions

Table: users

Description

We need a users table to ensure that we can differentiate the admin of the site (our client) from normal users. This is because our admin is able to create, edit, and delete posts, while our normal users can only like and comment on the admin’s posts. This table will store a username, password, email, and an isAdmin differentiator.

Columns

  • id: INT - primary_key, required
  • username: VARCHAR(50), required, UNIQUE
  • email: VARCHAR(100), required, UNIQUE
  • password_hash: VARCHAR(255), required
  • is_admin: BOOLEAN, required
  • created_at: TIMESTAMP, required

Relationships

  • One user can create many posts.
  • One user can create many comments.

Table: posts

Description

Since part of our website is a blog section where our clients can make posts, we need a way of storing and retrieving posts.

Columns

  • id: INT - primary_key, required
  • title: VARCHAR(255), required
  • description: TEXT, required
  • attachment: VARCHAR(255)
  • user_id: INT - foreign_key, required
  • created_at: TIMESTAMP, required

Relationships

  • Each post can have one user.
  • Each post can have many comments.

Table: comments

Description

Other users will be able to comment on our client's post. The comments table will store these comments.

Columns

  • id: INT - primary_key, required
  • content: TEXT, required
  • post_id: INT - foreign_key, required
  • user_id: INT - foreign_key, required
  • parent_comment_id: INT - foreign_key, optional
  • created_at: TIMESTAMP, required

Relationships

  • Each comment belongs to one post
  • Each comment belongs to one user
  • Comments can optionally belong to other comments (reply structure).

Section 4 - Functions

Client’s functionality

  • Sign in (SELECT in database)
  • Adding a post to the blog (INSERT into database)
  • Editing a post (UPDATE database)
  • Deleting a post (DELETE part of database)
  • Commenting and replying to comments (INSERT into database)
  • Opening post (SELECT in database)
  • Searching for post (SELECT in database)

Other users’ functionality

  • Creating account (INSERT in database)
  • Signing in (SELECT in database)
  • Commenting (INSERT into database)
  • Replying to comments (INSERT into database)
  • Opening post (SELECT in database)
  • Searching for post (SELECT in database)
